RB-Y1 T1~T10에서 SmolVLA 학습 및 평가

0️⃣ VLA와 SmolVLA란?

https://huggingface.co/blog/smolvla https://huggingface.co/lerobot/smolvla_base https://github.com/huggingface/lerobot

VLA(Vision-Language-Action) 모델은 카메라 영상(Vision)과 언어 지시문(Language)을 함께 보고 로봇 동작(Action)을 바로 출력하는 정책입니다. IL 실습의 BC 정책은 task 하나만 배웠지만, VLA는 지시문을 바꿔 가며 모델 하나로 여러 task를 수행합니다.

SmolVLA는 Hugging Face LeRobot 팀이 공개한 작은 VLA입니다(전체 4.5억 파라미터). 영상·언어를 이해하는 VLM(SmolVLM2-500M의 앞 16층)과, 그 정보를 받아 로봇 동작을 만드는 action expert로 이루어져 있습니다. action expert는 flow matching으로 한 번에 50 step 분량의 동작 묶음(action chunk)을 만듭니다. lerobot/smolvla_base는 커뮤니티 로봇 데이터로 미리 학습된 가중치이고, 이번 실습에서는 이것을 우리 RB-Y1 시뮬레이션 데이터로 미세조정(fine-tuning) 합니다.

이번 실습의 입력과 출력은 다음과 같습니다.

구분 내용
입력 영상 front(머리 카메라 480×640), left·right(손목 카메라 640×480 세로)
입력 상태 16차원: 오른팔 관절 7, 왼팔 관절 7, 오른손·왼손 그리퍼 열림 정도(0~1)
입력 언어 task의 지시문 (예: put the black bowl on the plate.)
출력 16차원 action × 50 step. 팔은 다음 step의 절대 관절 목표(rad), 그리퍼는 열기 1 / 닫기 0

전체 흐름: 오라클로 시범 수집 → LeRobot 데이터셋 변환·검증 → SmolVLA 학습 → task마다 50회 평가

2️⃣ 오라클 데이터 수집

사람이 키보드로 500개 시범을 모으기는 어렵습니다. 그래서 시뮬레이터의 정답 상태(물체·손잡이·서랍의 실제 위치)를 읽어 움직이는 스크립트, 즉 오라클(oracle)로 시범을 모읍니다.

(1) 동작 원리

  • 시범 하나 = 하위 동작의 고정된 순서입니다. 예: T1은 접근 → 파지 전 자세 → 파지 → 들기 → 운반 → 놓기 → 놓은 뒤 위로 → 준비 자세로 복귀.
  • 각 하위 동작을 시작할 때 정답 상태로 목표 위치를 계산하고, 그리퍼 끝(TCP)을 부드러운 직선 경로로 움직입니다.
  • 제어 경로는 키보드/VR 수집기와 같습니다: Differential IK(DLS) → 18개 관절 절대 목표, 관절 속도 제한 0.8 rad/s, 15fps(물리 1/105초 × 7).
  • 기록 형식도 키보드 수집기와 같은 raw 형식(<output>_raw/episode-*/)입니다. 그래서 기존 export_dataset.sh, --validate, replay_dataset.sh가 그대로 동작합니다.
  • 복구 동작은 없습니다. 재파지, 노이즈, 재시도를 하지 않습니다. 첫 시도가 실패한 seed는 저장하지 않고 다음 seed로 넘어갑니다(실패 수와 원인만 기록).
  • 오라클 자체에는 무작위성이 없습니다. 물체 배치만 seed(numpy.random.default_rng(seed))로 정해집니다.
  • 성공 판정 후 저장 직전에 원래 조건이 아직 성립하는지 한 번 더 확인합니다. success_original은 조건이 한 번 성립하면 3.5초 뒤 확정되므로, 그사이 물체가 미끄러져 조건이 깨진 시범도 성공으로 남을 수 있기 때문입니다(실패 원인 latched_then_undone).
Task 사용하는 팔 하위 동작
T1 왼팔 그릇의 로봇 쪽 테두리 집기 → 들기 → 접시 위로 운반 → 놓기 → 위로 → 준비 자세
T2 왼팔 T1과 같음 (쿠키 상자 위 그릇, 더 얕게 집기)
T3 왼팔 케첩 위에서 수직으로 집기 → 바구니 테두리 위로 들기 → 바구니 안에 놓기 → 준비 자세
T4 왼팔 손잡이에 접근 → 손가락 하나를 손잡이 뒤 틈에 걸어 잡기 → 14cm 당기기 → 놓고 위·뒤로 → 준비 자세
T5 오른팔 손잡이(세로 막대) 잡기 → 경첩 중심으로 원호를 따라 68° 열기 → 놓고 뒤로 → 준비 자세
T6 왼팔 손잡이 능선을 위에서 집기 → 수직축으로 0.9 rad 돌리기 → 놓고 위로 → 준비 자세
T7 왼팔 위 서랍 끝까지 당기기 → 그릇 테두리 집기 → 높이 들어 서랍 위로 → 서랍 앞쪽에 놓기 → 서랍에서 떨어진 자세
T8 왼팔 가운데 그릇 테두리 집기 → 뒤쪽 그릇 위로 운반 → 놓기 → 준비 자세
T9 왼팔 그릇을 열린 아래 서랍에 넣기 → 손끝으로 손잡이를 밀어 닫기(2단계) → 준비 자세
T10 왼팔 → 오른팔 수프(왼팔)를 바구니에 넣고 복귀 → 토마토 소스(오른팔)를 바구니에 넣고 복귀

(2) 수집 명령어

conda 환경 활성화

cd ~/lightwheel_rby1_transfer

cd ~/lightwheel_rby1_transfer

    ./vla_lab/collect_oracle.sh --task $T --num-demos 50 --seed-start 0
done
인자 기본값 설명
--task (필수) T1~T10
--num-demos 50 저장할 성공 시범 수
--seed-start 0 첫 시도의 배치 seed. 시도 k는 seed seed-start + k
--max-attempts 3 × num-demos 이 횟수만큼 시도하면 멈춤
--output ~/datasets/vla_lab/<task>/oracle LeRobot 데이터셋 폴더. raw는 <output>_raw
--joint-speed 0.8 관절 속도 제한(rad/s), 수집기 기본값과 같음
--video 없음 첫 성공 시범을 정면 카메라 mp4로 저장
  • 학습 seed는 0~9999 범위만 씁니다. 평가 seed는 100000번대라 겹치지 않습니다.
  • 수집이 중간에 끊기면 같은 명령을 다시 실행하십시오. <output>_raw/oracle_attempts.jsonl을 읽고 마지막 seed 다음부터 이어서 수집합니다.

4️⃣ SmolVLA 학습

(1) 학습 명령어

conda 환경 활성화

conda activate lerobot-arena

학습 실행 (T1~T10 멀티태스크 모델 1개)

cd ~/lightwheel_rby1_transfer
./vla_lab/train_smolvla.sh --output_dir ~/vla_lab_runs/smolvla_t1_t10
  • vla_lab/train_smolvla.sh는 LeRobot의 lerobot-train을 그대로 부르는 래퍼입니다. 아래 표의 값을 넣고, PyTorch가 GPU 메모리를 7.0GB까지만 쓰도록 막습니다(torch.cuda.set_per_process_memory_fraction). 넘으면 학습이 OOM으로 멈추므로, 끝까지 돌면 8GB GPU에서도 돈다는 뜻입니다.
  • 뒤에 붙인 인자는 기본값을 덮어씁니다. 예: --steps=300(짧은 시험), --batch_size=8.
  • --output_dir이 이미 있으면 LeRobot이 에러를 냅니다. 다른 이름을 쓰십시오.
  • 데이터셋 위치가 다르면 VLA_DATASET_ROOT=/path/to/RBY1-T1-T10-Oracle를 앞에 붙입니다.

소요 시간과 VRAM (조교 PC, RTX 3090 24GB)

항목 값
step당 시간 updt_s 0.455초 + data_s 0.017초. 로그 기준 실제 약 0.49초/step (8K→25K step: 8,301초)
25,000 step 약 3시간 23분 (0.488초 × 25,000. 다른 작업과 함께 돌린 이번 실행은 3시간 46분)
최대 VRAM 프로세스 6.47GB (nvidia-smi 6,624MiB), PyTorch 예약 6.15GB
체크포인트 하나당 1.3GB (optimizer 상태 포함), 6개 저장
  • 8GB GPU에서는 직접 재지 못했습니다. RTX 3090 대비 연산 성능(FP32 35.6 TFLOPS)과 메모리 대역폭(936GB/s)으로 비교하면 RTX 4060(15.1 TFLOPS, 272GB/s)은 약 2.4~3.4배, RTX 3070(20.3 TFLOPS, 448GB/s)은 약 1.8~2.1배 느릴 것으로 추정합니다. 25,000 step 기준 약 6~11.6시간입니다(12시간 목표 안이지만 RTX 4060급에서는 여유가 적습니다).
  • 시간이 부족하면 --steps와 --policy.scheduler_decay_steps를 같이 줄이십시오.

  • 실패의 57%(140/247)는 파지 실패(물체를 밀거나 넘어뜨리고 들지 못함)입니다. 단계별 분석은 vla_lab/reports/failure_analysis.md에 있습니다.
  • 신뢰구간이 넓습니다(50회 기준 ±10~15%p). 두 설정을 비교할 때는 구간이 겹치는지 보십시오.
  • 같은 명령을 다시 돌리면 결과가 조금 다를 수 있습니다. 정책 추론은 같은 입력·seed에서 완전히 같지만, 시뮬레이터의 RTX 렌더링이 같은 장면에서도 픽셀을 조금씩 다르게 그립니다(평균 2~3/255). 이 차이 때문에 같은 seed라도 에피소드 결과가 바뀔 수 있습니다. 조교가 T1·T5를 두 번 평가했을 때 성공 수는 45→46, 38→39로 거의 같았지만, seed별 결과는 T1 5개, T5 11개가 서로 달랐습니다(vla_lab/reports/eval_determinism.md). 오라클 수집과 물리는 결정적이라 같은 seed면 시범이 완전히 같습니다.

6️⃣ VRAM 확인 방법

모든 단계는 VRAM 8GB 이하에서 돌도록 맞췄습니다. 각자 PC에서 직접 확인하는 방법입니다.

(1) 다른 터미널에서 1초마다 보기

nvidia-smi --query-compute-apps=pid,used_memory --format=csv -l 1

(2) 명령을 감싸서 최대값 기록하기

vla_lab/scripts/vram_monitor.py는 위 명령을 1초마다 실행해 모든 프로세스의 합계를 CSV로 남기고, 끝나면 최대값을 출력합니다.

7️⃣ 문제 해결 FAQ

조교가 이 자료를 만들며 실제로 겪은 문제만 적었습니다.

증상 원인과 해결
ModuleNotFoundError: No module named 'lerobot' lerobot-arena에 LeRobot이 ~/lerobot(editable)로 설치돼 있는데 그 폴더가 지워진 경우. cd ~ && git clone --branch v0.4.3 https://github.com/huggingface/lerobot.git 로 같은 위치에 되돌리면 재설치 없이 import됩니다.
FileNotFoundError: Missing external asset directory: .../rby1-sim-isaac 로봇 USD 레포가 없음. cd ~ && git clone https://github.com/cailab-hy/rby1-sim-isaac 또는 이미 있는 위치를 export RBY1_SIM_ROOT=/path/to/rby1-sim-isaac로 지정.
레포를 ~/lightwheel_rby1_transfer가 아닌 곳에 clone함 IsaacLab_RS, rby1-sim-isaac를 레포의 상위 폴더에서 찾습니다. export RBY1_ISAACLAB_ROOT=~/IsaacLab_RS, export RBY1_SIM_ROOT=~/rby1-sim-isaac를 설정하십시오(조교가 7단계 재현에서 이 방법으로 확인).
환경 확인에서 SmolVLA weights: MISSING, 학습 시작 시 Hub 관련 에러 위 추가 설치의 hf download 두 줄을 실행. 학습 스크립트는 오프라인 모드라 자동으로 받지 않습니다.
학습 중 torch.OutOfMemoryError: CUDA out of memory ... 7.00 GiB allowed 래퍼가 건 7.0GB 상한을 넘은 것. --batch_size를 줄이십시오. 조교 PC에서 batch 32는 bf16 혼합정밀도로도 이 에러가 났고, batch 16은 PyTorch 6.1GB(프로세스 6.4GB)였습니다.
데이터셋 합치기 끝에 terminate called without an active exception 영상 처리 스레드가 종료 순서 때문에 내는 메시지입니다. 바로 앞에 MERGED ... 500 episodes가 나왔으면 정상이며, 데이터셋은 그대로 로딩됩니다.
Isaac Sim 로그에 [Warning], [Error] ... torch_dtype is deprecated 등이 많이 나옴 정상입니다. 수집기는 [T1] attempt ..., 평가는 [T1] episode ... 줄만 보면 됩니다.
T3 시범을 replay_dataset.sh --mode action으로 재생했는데 replayed_success_original: false 관절은 기록과 같게 움직이지만(최대 0.002 rad 차이), 케첩을 바구니 안에 떨어뜨리는 순간의 접촉이 민감해서 넘어지는 방향이 달라질 수 있습니다. 조교 PC에서 10개 task 중 T3 하나만 재생 성공이 재현되지 않았습니다. 같은 seed로 다시 수집하면 결과가 완전히 같습니다.
FileExistsError: Output directory ... already exists (학습) LeRobot은 기존 결과 폴더를 덮어쓰지 않습니다. --output_dir을 새 이름으로 바꾸거나, 이어서 학습하려면 --resume=true --config_path=...를 쓰십시오.

8️⃣ 더 발전시키려면

이번 baseline에는 일부러 넣지 않은 것들이 있습니다. 정답은 주지 않습니다. 질문과 단서만 적습니다.

  1. 복구 시범이 없다. 오라클은 항상 첫 시도에 성공한 깨끗한 시범만 보여 줍니다.
    • 정책이 그릇을 살짝 놓쳤을 때, 학습 데이터에 그 상황에서 어떻게 해야 하는지가 있었나요?
    • 단서: 평가 실패 영상에서 "처음 실수 직후" 장면을 보십시오. 그 상태에서 시작하는 시범을 만들 수 있을까요?
  2. 노이즈 주입이 없다. 오라클 경로는 매번 같은 모양입니다.
    • 학습 때 본 적 없는 약간 어긋난 상태에서 정책은 어떻게 행동할까요?
    • 단서: DART(Laskey et al., 2017). 시범을 기록할 때 실행 동작에만 작은 노이즈를 넣고, 기록하는 action은 원래 오라클의 것으로 두면 무엇이 달라질까요?
  3. 다양성 조절. 물체 배치 범위는 레포 기본값(randomization) 그대로입니다.
    • 범위를 넓히면 평가가 쉬워질까요, 어려워질까요? 시범 수는 얼마나 더 필요할까요?
  4. 시범 수. task당 50개입니다.
    • 25개, 100개로 바꾸면 성공률 곡선이 어떻게 변하나요? 어떤 task가 데이터에 가장 민감한가요?
  5. 학습 설정.
    • 평가 때 --n-action-steps 10으로 더 자주 다시 계획하면 접촉이 많은 T5, T9에서 결과가 달라질까요?
    • 체크포인트 5000/10000/15000/20000 중 어느 것이 가장 좋은가요? 손실(loss)이 낮을수록 성공률도 높은가요?
  6. 실패 분석. vla_lab/scripts/failure_analysis.py로 실패를 단계(접근·파지·운반·배치·시간 초과)별로 나눠 보고, 가장 많이 실패하는 단계를 먼저 공략하십시오.
