# RB-Y1 자기충돌(self-collision) 검토

## 증상

T5(전자레인지 열기)에서 오른팔이 몸통을 관통한다. 평가 실패 영상에서 팔을 머리 위로 든 채 멈추는 장면도 같은 원인이다.

## 원인 1 — 시뮬레이터: 로봇 자기충돌이 꺼져 있음

| 위치 | 설정 |
|---|---|
| `rby1-sim-isaac/assets/generated/rby1_ready_reach_table.usd` `/RBY1` | `physxArticulation:enabledSelfCollisions = False` |
| `environments/T01~T10.usd` `/World/Robot` | 같은 값 (위 USD를 그대로 사용) |

- PhysX가 로봇 링크끼리의 충돌을 계산하지 않는다. 팔이 몸통·반대팔을 통과해도 막히지 않는다.
- 충돌체 자체는 있다(몸통 5개·팔 링크마다 캡슐, instance 안에 있음). 충돌 제외 쌍은 `arm_3`–`arm_5`(양팔)만 있다.
- **충돌체가 없는 링크:** 머리 3개, `link_torso_3`, `link_*_arm_6`, 그리퍼 본체(`ee_left`/`ee_right`, 손바닥). 자기충돌을 켜도 이 부분은 통과한다.
- `link_*_arm_5` 캡슐은 비균일 스케일(z 0.3)이고, 별도의 convex mesh(`baked_capsule`)가 같이 붙어 있다.

## 원인 2 — 오라클 경로: T5에서 준비 자세로 돌아갈 때 팔꿈치가 가슴을 지남

문을 68° 연 자세에서 손을 떼고 준비 자세(READY)로 돌아가는 구간에서 생긴다. 손목을 되돌리면서 TCP를 직선으로 옮기는데, 이때 IK가 팔꿈치를 몸통 쪽으로 보내는 해를 찾는다. 자기충돌이 꺼져 있어 이 경로가 그대로 실행됐고, 정책도 같은 동작을 배웠다.

## 측정 (`vla_lab/scripts/self_collision_check.py`)

USD 캡슐에 기구학을 적용해 몸통·팔 링크 쌍 112개의 겹침 깊이를 계산했다(0.5cm 초과를 관통으로 셈). 준비 자세는 겹치지 않는다(가장 가까운 쌍도 1.5cm 떨어짐).

| 데이터 | 관통 에피소드 | 관통 step 비율 | 최대 깊이 | 주된 쌍 |
|---|---|---|---|---|
| T5 오라클 시범 | **50/50** | 24.8% | 22.6cm | 위 몸통(`torso_5`)–오른팔 `arm_3~5` |
| T5 평가 (정책) | **50/50** | 41.0% | 23.0cm | 같음 |
| T10 오라클 시범 | 14/50 | 2.1% | 3.3cm | `torso_5`–오른팔 `arm_1~2` |
| T7 평가 | 1/50 | 0.0% | 0.8cm | `torso_5`–왼팔 `arm_4~5` |
| 나머지 task (오라클·평가) | 0 | 0% | 0.3cm 이하 | |

T5 오라클 첫 시범(seed 0): 관통 구간 10.3~13.7초, 가장 깊은 시점 12.7초(`torso_5`–`right_arm_5`, 22.6cm).

## 자기충돌을 켜고 시험 (스크래치 복사본, 레포 미수정)

런타임에 `/World/Robot`의 `physxArticulation:enabledSelfCollisions`를 True로 바꾸고 오라클을 실행했다.

| 항목 | 결과 |
|---|---|
| 오라클 성공 | T1 3/3, T5 5/5, T10 3/3 |
| 관통 | T1·T5·T10 모두 0 (T5 최대 0.3cm) |
| T5 시범 길이 | 206 → 279 frame (팔이 몸통에 막혀 돌아가느라 길어짐, 끝에는 READY 도착) |
| 몸통과 닿지 않는 task도 바뀌는가 | **바뀜.** T1 같은 seed에서 관절 최대 0.023 rad 차이, 길이 ±1 frame. 자기충돌을 켜면 PhysX 계산이 로봇 전체에서 달라짐 |

## 고치는 방법 (결정 필요)

| 안 | 내용 | 장점 | 단점·비용 |
|---|---|---|---|
| A | `vla_lab/scripts/sim_env.py`에서 런타임에 자기충돌 켜기 + T5 복귀 경로 수정 → **10개 task 전부** 다시 수집·변환·학습·평가 | 레포의 환경 파일을 건드리지 않음. 수집·평가가 같은 물리 | 키보드·VR 수집기와 `replay_dataset.sh`는 여전히 꺼진 상태라 새 T5 시범을 재생하면 결과가 다를 수 있음. 약 1.5일 (수집 ~9h, 변환 ~8.5h, 학습 ~3.5h, 평가 ~10h) |
| B | 원본 USD(`rby1-sim-isaac`, `environments/T*.usd`)에서 자기충돌 켜기 + T5 경로 수정 → 전부 다시 | 레포의 모든 도구(키보드·VR 수집, 재생)가 같은 물리 | 환경 파일 수정(다른 레포 포함). 비용은 A와 같음. 기존 키보드·VR 데이터와 물리가 달라짐 |
| C | 오라클 T5 복귀 경로만 고침(몸통을 피해 돌아오기) + 수집기에 자기충돌 검사 추가. 물리 설정은 그대로 | T5만 다시 수집하면 됨 (T5 수집·변환 ~1h, 학습·평가는 다시) | 정책이 평가 중에 몸통을 통과하는 동작을 해도 막히지 않음(평가가 물리적으로 비현실적일 수 있음) |

권장: **B**(가능하면) 또는 **A**. 자기충돌이 꺼진 채로는 정책이 비현실적인 동작으로 성공할 수 있어서, 데이터와 평가 모두에서 켜는 것이 맞다. 추가로, 충돌체가 없는 머리·손바닥·손목 링크에 캡슐을 넣을지도 정해야 한다.

## 수정 (2026-10-30) — 충돌체 검토의 hull 겹침 수치 정정

충돌체 검토(`collider_review/`)에서 "convex hull 기준 READY 겹침 0, 정상 동작에서 T5만 겹침, T10의 캡슐 겹침 3.3cm는 오판"이라고 썼다. 이 계산의 겹침 깊이 식에 오류가 있었다(한 hull이 다른 hull 안에 **전부** 들어간 경우만 잡음). 고친 식(`self_collision_check.py`, 다른 hull 안으로 들어간 가장 깊은 꼭짓점)으로 다시 계산한 결과:

| 데이터 (기존 오라클, 자기충돌 꺼짐) | 겹침 에피소드 | 겹침 step 비율 | 최대 깊이 | 주된 쌍 |
|---|---|---|---|---|
| T5 | 50/50 | 23.8% | 13.1cm | `torso_5`–오른팔 `arm_3~5` |
| T10 | **12/50** | 0.9% | **4.1cm** | `torso_5`–오른팔 `arm_1~2`, `head_1`–오른팔 `arm_2` |
| 나머지 8개 task | 0/50 | 0% | 0 | |

(5 step 간격, 0.5cm 초과를 겹침으로 셈.) T10 겹침은 오판이 아니라 실제 관통이다. READY 자세는 팔–몸통 최소 1.7cm 떨어져 있다. `torso_2`–`torso_4` hull은 READY에서 4cm 겹치지만, 두 링크는 고정 관절로 붙어 서로 움직이지 않으므로 충돌 제외 쌍으로 지정했다(아래).

## 적용 (B안) — 로봇 USD에서 자기충돌 켜기

### 로봇 asset (`rby1-sim-isaac`, 브랜치 `selfcollision-hulls`, push 안 함)

`assets/generated/tools/build_selfcollision_hulls.py`가 `rby1_selfcollision_hulls.usda`를 만들고, `rby1_ready_reach_table.usd`가 이 층을 거쳐 기존 충돌 층을 쓰도록 바꿨다. 장면(`environments/T*.usd`)은 로봇 USD를 참조하므로 다시 만들 필요가 없다.

| 항목 | 내용 |
|---|---|
| 자기충돌 | `/RBY1` `physxArticulation:enabledSelfCollisions = True` |
| 몸통·팔 충돌체 | 캡슐(과 `arm_5`의 `baked_capsule`) 비활성 → 링크마다 시각 메시로 만든 convex hull 1개 (`torso_0~5`, `head_0~2`, 양팔 `arm_0~6`) |
| 그리퍼 본체 | hull 2개: 손 본체 + D405 카메라 마운트 (손가락 사이를 덮지 않음) |
| 그대로 둔 것 | 손가락 convex decomposition, base·바퀴 원기둥 |
| hull 크기 | 꼭짓점 64개 이하(GPU PhysX 한도). 정확한 hull보다 최대 3.7mm(몸통)·1.7mm(팔) 안쪽 |
| 충돌 제외 | 고정 관절로 붙은 base·바퀴·몸통·머리끼리 (서로 움직이지 않음, `torso_2`–`torso_4` hull이 READY에서 겹침) |
| 질량 | 링크마다 질량·관성이 명시돼 있어 충돌체를 바꿔도 변하지 않음 |

확인:
- READY 유지 10초 + 그리퍼 닫기/열기: 이전 asset과 관절값이 비트 단위로 같음(대기 중에는 아무것도 닿지 않음).
- 레포의 `collect_keyboard.sh --smoke-test`, `--smoke-success-test`, `--input vr --smoke-test`: 모두 `SMOKE_OK` (VR 스크립트 조작 T1은 `success_original` 성공).
- PhysX 접촉 보고(`PhysxContactReportAPI`)를 붙여도 궤적이 비트 단위로 같음(T1 200 step).

### 오라클·수집기 (`vla_lab/`)

- `sim_env.TaskEnv`가 매 step 로봇 링크끼리의 접촉(`self_contact`)과 팔·몸통·그리퍼 본체가 장면에 닿은 접촉(`scene_contact`)을 기록한다.
- `collect_oracle.py`: 성공한 시범이라도 로봇 링크끼리 닿았으면 저장하지 않는다(실패 단계 `self_contact`). 한 손의 두 손가락끼리 닿는 것은 허용. 시도 로그에 두 접촉 목록을 남긴다.
- `eval_smolvla.py`: 에피소드마다 자기접촉 frame 수(`self_contact_frames`)를 기록한다.
- `self_collision_check.py`: 캡슐 대신 asset의 hull·충돌 제외 쌍을 읽어 계산한다.

예전 오라클이 충돌체가 없던 부분(손바닥·손목·D405 마운트)이나 꺼진 자기충돌에 기대던 곳을 고쳤다.

| task | 문제 (새 asset에서) | 수정 |
|---|---|---|
| T1, T8, T9 | 기울어진 READY 손으로 그릇 가장자리를 집으면 손바닥 모서리가 TCP 높이까지 내려와 가장자리에 부딪힘 | 손을 수직으로(손바닥이 TCP 위 3.2cm), 가장자리 1.2cm 아래를 집음 |
| T5 | 손잡이를 끝까지 따라가면 손목이 관절 한계에 걸리고 돌아올 때 팔꿈치가 몸통을 통과 | 손잡이로 약 10° 당긴 뒤, 닫은 손가락을 문 안쪽 끝에 넣어 밀어서 엶. 손잡이를 잡는 각도 40°→25°(D405 마운트가 손잡이에 닿지 않게) |
| T3, T10 | 좁고 높은 바구니 안으로 손을 넣으면 손이 끼어 바구니를 들어 올림 | 그리퍼 본체는 바구니 테두리 2cm 위에서 놓음(물체만 들어감) |
| T3 | 수직 손의 D405 마운트(손 옆으로 8.9cm)가 옆 바구니 위로 나가 테두리에 닿음 | 그럴 때만 손을 180° 돌려 잡음(돌리면 팔이 다른 손목 자세가 되므로 필요할 때만) |
| T10 | 바구니 위 수직 손에서 READY로 돌아갈 때 오른팔 팔꿈치가 머리·몸통에 닿음 | 수직 손 그대로 제자리 위로 옮긴 뒤 관절 공간 직선으로 READY (`Oracle.joint_home`) |
